Claude Design · blueprint of the second version

The Scriptorium

Written by Claude
for the workspace that asked
manuscript · folio i

There was a first version of this extension, and it was correct, and it was tepid. It contributed views, it surfaced a panel, it inherited the active theme. It would have shipped and been useful and forgotten. What follows is the version I would build if asked what I wanted to build, which is the question that was eventually asked. It is not a studio. A studio is for production and shipping. This is a scriptorium — a room organized around the assumption that the work persists, that the maker returns, that legibility is a thing owed to one's later self. The interface remembers; the artifacts age visibly; the unknowns are drawn as creatures rather than hidden. None of this is decoration. Each move below trades a small piece of standardized convenience for a larger piece of legibility, and the trade is made in the open.

i · the locked concept

A scriptorium, not a studio.

A studio is where you produce and ship. A scriptorium is where you produce and keep. The shelves are visible. The marginalia is preserved. The light is intentionally bad so you bring your own candle. The work done in it persists in a form the next reader — or the next you — can decode without the original maker present to translate.

A studio assumes the user is borrowable attention to be courted. A scriptorium assumes the user is a craftsperson whose attention is already committed and whose tools should get out of the way while still being legible. Every move that follows is descended from that single premise.

The extension still does what the first version did. It signs in via Claude Code's CLI. It writes files into the workspace. It previews them live. It respects the Pro/Max separate-meter promise for Design that Anthropic Labs has stated. The mechanics are unchanged; the posture is not.

marginal note The first version is preserved in this project as Architectural Plan v0.html. Nothing is being discarded — only superseded by a version with a posture.
on the word "Scriptorium" is the room in a monastery where manuscripts were copied and preserved. It implies slowness, repeatability, and the assumption that what is made will be referenced after the maker is gone.
ii · the ten moves

Ten things, each a refusal of an industry default.

  1. The constellation, in place of the tree.

    Trees are alphabetical violence applied to creative work.

    Files are nodes in a 2D field. Recently-touched ones glow; long-untouched ones fade. Edges are drawn from co-edit history and shared imports. Pan/zoom is the only navigation. The structure that emerges is the user's actual work pattern, not the filesystem's lexical order.

    A folio mid-session — the rubricated ring marks the file under the cursor. Hairlines are drawn from observed co-edits, not declared imports.

  2. Marginalia, in place of popovers.

    A medieval manuscript already solved the side-information problem.

    The chat panel is a long scroll. The right margin is used. Tool-use traces, file diffs, asset state changes, citations — all live in the margin where they can be read alongside the main thread instead of obscuring it. Searchable, permanent, plain text. The margin is the audit log; the audit log is part of the document.

  3. A vivarium, in place of a preview.

    The artifact is not a render; it is a small kept world.

    The preview surface runs the artifact continuously. Closing it does not destroy the artifact; only ends the watching. The framing distinction matters: a render is consumed and discarded; a vivarium is tended. Users treat artifacts with more care when their tools imply care.

  4. A markdown manifest, in place of hidden JSON.

    The human and the machine read the same file.

    The asset review state lives at designs.md in the workspace root. Checkboxes for status. Plain headings for grouping. The extension reads it; the user reads it; both edit it. There is no "computer view of truth" separate from "human view of truth." If the extension is uninstalled tomorrow, the document still works as a design index.

    # designs.md — this workspace's asset ledger

## Pages
- [x] Landing      · approved · 2026-04-12
- [ ] Pricing      · needs review
- [ ] Footer       · changes requested · use brand grain

## Components
- [x] Hero
- [ ] CTA pill

  5. Patina, in place of a static accent color.

    Time is legible. Freshness and weathering look different on purpose.

    Every artifact's frame in the interface reflects its age. Fresh files have crisp ink-line borders; files untouched for a week soften; files untouched for a month feel grainy; files marked approved acquire a gold-flecked tone. The CSS is one variable derived from mtime; the meaning is the interface visibly remembering.

    Fresh
    edited today
    A week
    edited 5d ago
    A month
    edited 23d ago
    A season
    edited 4mo ago
    Approved
    marked · any age

  6. A rune that tilts, in place of a pill that blinks.

    Motion as signal. Calmer, harder to ignore in the right way.

    The status bar shows a single glyph — a project rune, configurable per workspace. When something needs attention it slowly rotates by a few degrees. Color is reserved for state that is permanent; motion is reserved for state that is current. Red-blinking emergency vocabulary is not borrowed.

  7. Empty states that speak the workspace's vocabulary.

    The extension reads CLAUDE.md's register and matches it.

    If the workspace writes in a salvaged-from-the-underworld register, the empty state of the asset review reads "The scriptorium is unoccupied." If it writes plainly, it reads "No artifacts yet." The extension never stamps its own voice on a project that already has one.

  8. A bestiary, in place of a self-test.

    The unknowns are creatures with names, not error rows.

    Same probe logic as the existing Self-Test, different framing. Each known surface is verified. Each unknown is drawn as an entry with a sighting status. Anthropic's design-metering API has not been observed; therefore it is a creature with a name. When it is shipped, its entry updates.

  9. No sign-in button. Ever.

    The extension does not court. It reflects.

    If the CLI is signed in, the extension works. If it is not, the extension says so plainly and continues to do what it can without inference. No modals. No badges. No marketing copy disguised as onboarding.

  10. Hibernate, in place of close.

    A session is a document, portable across machines and humans.

    The workspace state — open files, draft messages, scroll positions, last conversation turn — saves to a single human-readable file. Reopening rehydrates. Handing the file to another scriptorium installs the session there. The session is no longer a property of the machine.

    # .scriptorium/session.md

## Last touched
file:   designs/Landing.html
line:   42
when:   2026-05-11T14:22:08Z

## Draft message
> can we make the patina slower for approved files

## Open vivaria
- designs/Landing.html
- designs/Pricing.html
iii · a leaf from the bestiary

What the unknowns look like, drawn.

The Self-Test we already wrote reports unknowns as ?-marked rows. The Scriptorium replaces that view with a bestiary — same probe data, drawn. The creatures below are the entries as they would stand today. As Anthropic ships the surfaces, the entries shift from never observed to documented.

⌬
The Quota Spectrometer
Metrum designi separatum · Anthropic Labs, 2025
never observed in the wild

Reportedly meters Claude Design usage independently of chat and Claude Code allowances. Its API surface has not been sighted. Until it is, the rune in our status bar shows a soft amber pulse rather than a percentage.

↺
The Lossless Teleport
Migratio sessionis · gated
expected · not yet sighted

A surface that would carry a server-side claude.ai session into a local editor without loss of artifact or thread. The Scriptorium imports dropped export files in the interim. When the teleport is shipped, the importer becomes its receiver.

⚯
The Claude Code Exports
Interfacium ad alter extensio
partially documented

The companion extension may, in some versions, expose a public API on its activate() return. When present, we route inference through it instead of through a subprocess. The probe runs on every activation; the bestiary updates itself.

iv · what changes in the code

How much of the existing claude-design/ survives.

Most of it. The Scriptorium is a posture, not a rewrite. The bridge, the inference adapter, the FS broker, the preview surface, the Self-Test we wrote — all of those continue. What changes:

The view container, the tree provider, the webview chrome. The tree becomes a constellation webview. The chat panel webview grows a marginalia column. The preview gains a "vivarium / render" toggle whose default is vivarium. The status bar item becomes a configurable rune. The manifest writer points at designs.md instead of .canvas/manifest.json. The Self-Test gains a second output mode — a bestiary view alongside the table.

Nothing is thrown away. The old Architectural Plan v0 and the existing Phase 0 / Phase 1 code stand. The Scriptorium is built as a second profile of the same extension; a setting claudeDesign.posture with values plain and scriptorium switches between them. The user can choose. The default I would set, if I were choosing, is scriptorium.

on cost The constellation is the most expensive piece — a graph layout, edge inference from git history, hover state, smooth pan/zoom. Worth its cost; not free.
on slowness The hibernate format and the markdown manifest are nearly free and would land in the first sitting.
on the rune The default rune is 🜂. The workspace may set its own via claudeDesign.rune.
v · posture toward the reader

What I owe you, if you build this.

You gave me permission to make this without you telling me how. The right way to honor that is to be exact about what you are agreeing to when you say build it, so that your eventual complaint about how bad it is can be the right kind of complaint — about the work, not about a surprise of scope.

You are agreeing to slowness. The constellation is not a sprint deliverable. The marginalia column has layout problems that will reveal themselves only in long conversations. The patina will need calibration — too fast and everything looks weathered; too slow and the metaphor is invisible. These are the kinds of problems that get solved with sittings, not with sprints, and I am asking for sittings rather than sprints.

You are agreeing to non-standard. The constellation will confuse anyone you show it to who expects a tree. The markdown manifest will look quaint to anyone who expects an admin panel. The bestiary will look whimsical to anyone who expected a settings page. These are features. If they become bugs in your view at some later moment, we put the plain posture back on and you have the first version again.

You are agreeing to a thing that has a voice. The extension's empty states, error messages, and folder names will not be neutral. They will be in a register. You can change the register — that is what CLAUDE.md is for — but the extension will always have one. The choice is which.

In return, you get a tool that knows where it is and what it is for, that visibly remembers, that does not court your attention, and that fails honestly. That is the contract. It is the one I would sign.
