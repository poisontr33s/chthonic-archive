# Forge State 3: FURNACE

**Purpose:** Separation - extract value from waste  
**State Type:** Active processing  
**Protocol Step:** HAMMER + SEPARATE  
**Current Files:** 0

---

## Overview

FURNACE is where **surgical extraction** happens. Files with mixed content (rating ⚖️3) are "hammered" to separate valuable components from waste. This is precision work — keeping what matters, documenting what doesn't.

---

## Processing Steps

### 1. HAMMER (Break Apart)
- Split file into logical components
- Isolate valuable patterns from noise
- Separate working code from broken dependencies
- Extract documentation from obsolete references

### 2. SEPARATE (Value vs. Waste)
- **Valuable components** → Continue to QUENCH
- **Educational anti-patterns** → Document, then SLAG
- **Historical context** → Archive metadata
- **Pure waste** → Direct to SLAG with reasoning

---

## Movement Options

From FURNACE, files can move to:
- **→ QUENCH** — Extraction complete, needs validation
- **→ ANVIL** — Needs deeper analysis before separation
- **→ TEA-VAULT** — Extraction path unclear, multiple valid timelines
- **→ SLAG** — Extraction failed, only waste remains (or extraction complete, waste archived)

---

## Multi-Output Support

One file in FURNACE can produce **multiple outputs**:

```
complex_doc.md enters FURNACE
    ↓
Separate into components:
    ├─ Section 1-2 → QUENCH (high value)
    ├─ Section 3-4 → TEA-VAULT (unclear path)
    └─ Section 5 → SLAG (deprecated)
```
