● Here's the problem. The compiled dist/extension.js uses ESM import syntax
  (line 2: import * as vscode from "vscode"), and package.json has "type": 
  "module". VSCode's extension host does not support ESM extensions — it
  requires CommonJS (require/module.exports).

  This is the root cause of your startup failure. VSCode will fail to load the
  extension because it can't process import statements in extension code.

  Issues found:

  1. ESM format not supported by VSCode extensions — The build command uses
  --format esm, but VSCode expects CJS. The "type": "module" in package.json 
  compounds this. The build script needs --format cjs and package.json should 
  drop "type": "module" (or the main entry should be .cjs).
  2. Duplicate </script> tag at src/extension.ts:285 — minor, browsers handle
  it, but it's sloppy.
  3. engines.vscode says ^1.85.0 but vscode.lm API requires ~1.90+ — the 
  Language Model API (vscode.lm.selectChatModels) wasn't available until 1.90.
  If you're on Insiders this is likely fine, but the declared minimum is wrong.

  The fix for startup:

  In package.json:
  - Remove "type": "module" (or change to "commonjs")
  - Change build scripts from --format esm to --format cjs

  Then rebuild with bun run build.

  Want me to apply these fixes?
