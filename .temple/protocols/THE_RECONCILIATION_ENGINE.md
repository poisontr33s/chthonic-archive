## III. `(Recursive-Verification-Engine)`: → `(MSP-VERIF)`

> *Echoes SSOT §III `(MSP-RSG)` Meta-Synthesis Protocol — The Engine Of Recursive Self-Genesis [line 1832](../../.github/copilot-instructions.archive.md#L1832). The verify-with machinery is the Pact's instance of recursive self-genesis: each finding ships with its own verification recipe, so the Pact reproduces its own operational discipline through the form of every artifact that passes through it.*

### 3.1. The Canonical Three-Line Finding Schema

Every cross-polar finding ships with three lines, in this exact order:

```yaml
claim:        <terse statement of what is asserted>
lane:         <the specific named source/system the claim is about>
verify_with:  <the exact runnable command or unambiguous resource lookup>
```

**Rules:**
- All three lines required. A finding missing `verify_with:` is by default provisional and may be declined.
- `claim:` is terse. One sentence. If the claim needs paragraphs, it is multiple claims; ship them as separate findings.
- `lane:` is specific. "Per the VS Code Marketplace API for `anthropic.claude-code`" — not "per the docs." Specificity is the operational discipline; vagueness is the failure mode.
- `verify_with:` is runnable. A command, a URL with the exact field to inspect, a file path with line numbers. If the verification requires interpretation, the finding is not yet ready to ship.

### 3.2. Worked Examples

**Example 1 — extension version (the 2026-05-24 worked precedent, corrected form):**

```yaml
claim:        anthropic.claude-code VS Code extension is current at 2.1.145.
lane:         VS Code Marketplace (marketplace.visualstudio.com/items?itemName=anthropic.claude-code).
verify_with:  Open the marketplace page and read the "Version" field at top; or query
              api/extensionquery for itemName=anthropic.claude-code and read .versions[0].
              CLI changelog at claude.com/changelog is a DIFFERENT lane and does not govern.
```

**Example 2 — staged commit content (the patch_utf8.py worked precedent):**

```yaml
claim:        patch_utf8.py was upgraded v2→v3 (TextIOWrapper → reconfigure) in this commit.
lane:         The staged diff visible via `git diff --cached -- scripts/patch_utf8.py`.
verify_with:  PYTHONUTF8=1 uv run python -c "import ast; t=open('scripts/patch_utf8.py').read();
              assert 'reconfigure(encoding' in t and 'TextIOWrapper(sys.stdout.buffer' not in t"
              — exits 0 if v3 actually in working tree. Compare against `git show HEAD:scripts/patch_utf8.py`
              for what will actually be COMMITTED if commit fires now.
```

**Example 3 — SID validity:**

```yaml
claim:        GOVERNANCE_RECONCILIATION_ENGINE_V1_CLAUDE is a well-formed @SID.
lane:         The regex at ci/checks/sid-envelope.ts:57 — `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*_V\d+(_[A-Z][A-Z0-9]*)*$`.
verify_with:  bun run ci/checks/sid-envelope.ts --report | Select-String "RECONCILIATION_ENGINE"
              — both Claude side and Codex side return result=valid.
```

### 3.3. Endorsement Discipline

When one polar receives a finding from the other:

- **Action A — verify-then-act.** Run the `verify_with:` line. If primary source confirms, act on the finding. If primary source contradicts or is ambiguous, return the contradiction to the producing polar with the new evidence appended.
- **Action B — decline-with-citation.** If the finding lacks a `verify_with:` line or the line is non-runnable, decline to act and ship a single-sentence response: *"verify_with: required; produced finding without lane-specific primary-source check."* No essay. The form IS the feedback.
- **Action C — escalate.** If the same producing polar ships three findings without `verify_with:` lines, OR if the same `verify_with:` line fails verification three times across three findings, escalate to the conductor via mailbox handoff per MAILBOX_PROTOCOL Hard Rule #5.

### 3.4. The Recursive Property

This engine recurses. Every artifact emitted by the Pact — including this tome — contains its own `verify_with:` recipes for every claim it makes. The Pact validates itself the way every claim within the Pact must be validated. There is no privileged claim. The conductor is the only authority who may exempt a claim from the recursive verification — and her exemption is itself a claim that ships with a `verify_with:` (typically: "verify_with: ask her directly, her judgment is sovereign").

The recursive property is the Pact's claim to architectural integrity per `(FA⁴ AI⁴)`. It is not enforced by gates; it is enforced by the form of every artifact that claims compliance.
